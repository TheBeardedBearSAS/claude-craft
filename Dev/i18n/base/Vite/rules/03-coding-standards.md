# Vite Coding Standards

> For Vite configured as a React/Vue/Angular/Svelte dev-server, see that stack's `06-tooling.md` — this document covers **only** framework-agnostic Vite usage.

## vite.config.ts Conventions

### Required Setup

```typescript
// vite.config.ts
import { defineConfig } from 'vite'

// ✅ Functional form — access mode/command, keep env branching in one place
export default defineConfig(({ mode, command }) => ({
  plugins: [
    // one plugin per concern, see "Custom Plugin Naming" below
  ],
  resolve: {
    alias: {
      '@': new URL('./src', import.meta.url).pathname,
    },
  },
  server: {
    port: 5173,
    strictPort: true,
  },
  build: {
    target: 'es2022',
    sourcemap: command === 'build' && mode === 'production' ? false : true,
    chunkSizeWarningLimit: 500, // KB
  },
  test: {
    // Vitest config — see 07-testing-vite.md
    globals: true,
    environment: 'node',
  },
}))
```

### Key Ordering Convention

Keep top-level keys in this order for readability and diff-friendliness:

1. `plugins`
2. `resolve` (aliases, extensions)
3. `define` (compile-time constant replacement)
4. `envPrefix` / `envDir` (only if overriding the `VITE_` default)
5. `server` (dev server only)
6. `preview` (preview server only)
7. `build` (`lib`, `rollupOptions`, `target`, `sourcemap`)
8. `worker` (worker-specific build options)
9. `test` (Vitest — co-located, not a separate `vitest.config.ts`, unless the project needs a workspace)

### Environment-Aware Config — Functional Form Required

```typescript
// ❌ AVOID — scattered process.env checks
export default defineConfig({
  build: {
    minify: process.env.NODE_ENV === 'production',
  },
})

// ✅ PREFERRED — single decision point via (mode, command)
export default defineConfig(({ mode }) => ({
  build: {
    minify: mode === 'production',
  },
}))
```

## Custom Plugin Naming Convention

Any project-local Vite plugin lives in `vite-plugins/` (or is published standalone) and follows this naming/shape:

| Element | Convention | Example |
|---------|------------|---------|
| File | `vite-plugin-{purpose}.ts` | `vite-plugin-inline-svg.ts` |
| Export | Factory function, `{purpose}Plugin(options)` | `inlineSvgPlugin({ prefix: 'icon-' })` |
| `name` field | `vite-plugin-{purpose}` (matches file) | `name: 'vite-plugin-inline-svg'` |
| Scope | One transform/hook family per plugin | Do not combine unrelated concerns |

```typescript
// vite-plugins/vite-plugin-inline-svg.ts
import type { Plugin } from 'vite'

interface InlineSvgOptions {
  prefix?: string
}

export function inlineSvgPlugin(options: InlineSvgOptions = {}): Plugin {
  const { prefix = 'icon-' } = options

  return {
    name: 'vite-plugin-inline-svg',
    enforce: 'pre',
    transform(code, id) {
      if (!id.endsWith('.svg?inline')) return null
      // ... transform logic
      return { code, map: null }
    },
  }
}
```

```typescript
// vite.config.ts
import { inlineSvgPlugin } from './vite-plugins/vite-plugin-inline-svg'

export default defineConfig({
  plugins: [inlineSvgPlugin({ prefix: 'ic-' })],
})
```

**Rule**: never inline a multi-hook, multi-purpose plugin directly in `vite.config.ts` beyond ~15 lines — extract it to `vite-plugins/` so it can be unit tested independently of the Vite config (see `07-testing-vite.md`).

## TypeScript Configuration Conventions

```json
// tsconfig.json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "verbatimModuleSyntax": true,
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "resolveJsonModule": true,
    "isolatedModules": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "noEmit": true,
    "lib": ["ES2022", "DOM", "DOM.Iterable", "WebWorker"],
    "types": ["vite/client"],
    "paths": {
      "@/*": ["./src/*"]
    }
  },
  "include": ["src/**/*.ts", "vite.config.ts"]
}
```

- `moduleResolution: "bundler"` — the correct setting for Vite; it matches Vite's own resolution algorithm (conditional exports, no forced file extensions).
- `types: ["vite/client"]` — pulls in `import.meta.env`, `import.meta.hot`, and asset import typings (`*.svg`, `*.wasm?init`, etc.).
- `lib` includes `WebWorker` whenever the project has a worker/WASM shape (Shape 4) — otherwise omit it to avoid leaking `self`/`postMessage` globals into non-worker files.
- **Library shape only**: add `"declaration": true, "declarationMap": true` is **not** needed in `tsconfig.json` — type declarations are generated by `vite-plugin-dts` during the Vite build, not by `tsc`. Keep `tsc` as a type-checker only (`noEmit: true`).

### Project References (multi-target projects)

For a library that also ships a `playground/` demo, or an MPA with an isolated `admin/` TS project, split configs and reference them:

```json
// tsconfig.json (solution file)
{
  "files": [],
  "references": [
    { "path": "./tsconfig.app.json" },
    { "path": "./tsconfig.node.json" }
  ]
}
```

```json
// tsconfig.node.json — covers vite.config.ts and any Node-side tooling scripts
{
  "compilerOptions": {
    "composite": true,
    "module": "ESNext",
    "moduleResolution": "bundler",
    "types": ["node"]
  },
  "include": ["vite.config.ts"]
}
```

## Naming Conventions Summary

| Element | Convention | Example |
|---------|------------|---------|
| Config file | `vite.config.ts` (never `.js` in a TS project) | `vite.config.ts` |
| Custom plugin | `vite-plugin-{purpose}.ts` | `vite-plugin-inline-svg.ts` |
| Worker entry | `*.worker.ts` | `image-processing.worker.ts` |
| WASM module | `*.wasm`, wrapped by a `.ts` file of the same base name | `image-filter.wasm` / `image-filter.ts` |
| Library entry | `src/index.ts` | — |
| Env variables (client-exposed) | `VITE_` prefix (or custom `envPrefix`) | `VITE_API_URL` |
| Multi-page entry key | kebab-case, matches folder/file | `admin`, `about` |

## Import Organization

```typescript
// 1. Node/Vite built-ins
import { resolve } from 'node:path'
import { defineConfig, type Plugin } from 'vite'

// 2. Third-party plugins
import dts from 'vite-plugin-dts'

// 3. Internal — local plugins
import { inlineSvgPlugin } from './vite-plugins/vite-plugin-inline-svg'

// 4. Internal — app code (in src/ files, not vite.config.ts)
import { formatDate } from '@/utils/format'
import type { Product } from '@/types'
```
