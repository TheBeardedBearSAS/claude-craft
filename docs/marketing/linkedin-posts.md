## Post 2/7 - BMAD v6 Framework (v4.2.0)

**Planification** : Vendredi 30 janvier 2026 a 18h00

### Texte du post

[2/7] De v4.1 a v5.2 : L'evolution de Claude-Craft

9 agents IA, 5 quality gates, 20+ commandes. BMAD v6 transforme claude-craft en veritable outil de gestion de projet.

BMAD (Build Measure Analyze Deliver) v6 ajoute une couche de project management complete a claude-craft :

- 9 agents specialises : Product Manager, Business Analyst, Architect, Product Owner, Scrum Master, Developer, QA, UX Designer, et un orchestrateur central (bmad-master)
- 5 quality gates avec seuils : PRD (>=80%), Tech Spec (>=90%), Backlog (INVEST 6/6), Sprint Ready (100%), Story DoD (100%)
- Routing par statut : backlog -> ready-for-dev -> in-progress -> review -> done (avec etat blocked)
- Batch processing : execution sequentielle ou parallele d'epics et sprints entiers
- Suivi TDD integre : chaque story track sa phase Red/Green/Refactor

En une commande (`/project:run-sprint`), vous lancez un sprint complet avec validation automatique a chaque etape.

Les agents ne sont pas des prompts. Ce sont des definitions Agent-as-Code avec roles, responsabilites et interactions formalisees.

Open source : https://github.com/TheBeardedBearSAS/claude-craft/blob/main/docs/AGENTS.md

## Post 3/7 - i18n 5 langues (v4.3.0)

**Planification** : Samedi 31 janvier 2026 a 10h00

### Texte du post

[3/7] De v4.1 a v5.2 : L'evolution de Claude-Craft

claude-craft parle 5 langues. Et ce n'est pas du Google Translate.

Avec la v4.3, chaque commande, chaque template, chaque message est disponible nativement en :
- Anglais (EN)
- Francais (FR)
- Espagnol (ES)
- Allemand (DE)
- Portugais (PT)

Ce n'est pas de la traduction automatique. Chaque fichier est adapte aux conventions techniques de la langue cible. Les termes metier restent en anglais quand c'est l'usage (sprint, backlog, hook), mais les instructions et guides sont rediges naturellement.

Ce que la v4.3 complete :
- 18 commandes BMAD v6 traduites en ES, DE, PT
- 12 commandes BMAD manquantes completees en FR
- Templates sub-agents, MCP, regles Python et Flutter finalises dans les 5 langues
- ~346 fichiers par langue, parite atteinte

Pourquoi c'est important ? Parce qu'un developpeur qui comprend ses outils dans sa langue travaille plus vite et fait moins d'erreurs. L'IA-assisted development ne doit pas etre reserve aux anglophones.

Open source : https://github.com/TheBeardedBearSAS/claude-craft

## Post 5/7 - Autonomous Sprint Conductor (v5.0.0)

**Planification** : Dimanche 1 fevrier 2026 a 10h00

### Texte du post

[5/7] De v4.1 a v5.2 : L'evolution de Claude-Craft

Lancez un sprint le soir. 5 stories terminees le matin.

L'Autonomous Sprint Conductor (ASC) est le changement le plus significatif de claude-craft depuis sa creation. Il execute un sprint entier sans intervention humaine.

Comment ca marche :
- `/common:ralph-sprint "Sprint 3" --overnight` lance l'execution
- L'ASC reclame automatiquement la prochaine story prete
- Le Recovery Engine classe les erreurs en 4 niveaux (transient, recoverable, degraded, blocked) et tente de les corriger
- L'Escalation Service met en file d'attente les problemes bloquants et notifie via Slack, Teams ou Discord
- Le mode `--parallel 3` traite jusqu'a 3 stories simultanement
- L'arret automatique a 6h du matin en mode overnight

Le circuit breaker autonome tente une recuperation avant de declencher. Les erreurs transitoires (timeout, rate limit) sont reessayees avec backoff exponentiel. Les erreurs recoverables (lint, tests, deps) sont auto-corrigees.

Le lendemain matin, vous avez un rapport detaille de ce qui a ete fait, ce qui a echoue, et ce qui attend votre decision.

L'IA ne remplace pas le developpeur. Elle fait le travail pendant qu'il dort.

Open source : https://github.com/TheBeardedBearSAS/claude-craft/blob/main/docs/AUTONOMOUS-SPRINT.md

## Post 6/7 - QA Recette (v5.1.0)

**Planification** : Dimanche 1 fevrier 2026 a 18h00

### Texte du post

[6/7] De v4.1 a v5.2 : L'evolution de Claude-Craft

Un bug corrige qui revient = un bug paye deux fois. C'est la Golden Rule de la QA Recette.

La v5.1 ajoute les tests d'acceptance automatises via le navigateur Chrome. Claude ouvre votre application, execute les scenarios, detecte les anomalies et genere les tests de regression.

Ce que fait la QA Recette :
- Genere un plan de test a partir des criteres d'acceptance de vos stories
- Execute les tests dans Chrome (navigation, clics, saisie, captures d'ecran)
- Classe les erreurs : visual, interaction, validation, logic, security, API
- Genere automatiquement des tests de regression (PHPUnit, Symfony WebTestCase, Behat)
- Compare les executions pour detecter les regressions

La Golden Rule : chaque bug trouve genere un test de regression. Ce bug ne doit plus jamais reapparaitre. Le registre `.recette/regression/registry.yaml` track tous les bugs et leurs tests associes.

6 categories de tests couvrent l'ensemble : validation des criteres d'acceptance, cas limites, gestion d'erreurs, UI/UX, performance, securite.

La session est recoverable : si le test est interrompu, `--resume` reprend au dernier checkpoint.

Tester manuellement une fois, c'est normal. Tester manuellement deux fois la meme chose, c'est du gaspillage.

Open source : https://github.com/TheBeardedBearSAS/claude-craft

## Post 7/7 - Claude Code 2.1.25 Optimization (v5.2.0)

**Planification** : Lundi 2 fevrier 2026 a 08h30

### Texte du post

[7/7] De v4.1 a v5.2 : L'evolution de Claude-Craft

40% -> 75% d'exploitation de Claude Code. C'est le gain de la v5.2.

Claude Code offre 13 types de hooks, des frontmatter YAML pour les agents, des skills configurables et un systeme de plugins. Avant la v5.2, claude-craft n'en exploitait que 40%.

Ce qui change :
- 3 nouveaux hooks : PostToolUseFailure (recuperation apres echec), PreCompact (backup avant compaction memoire), SessionEnd (metriques, cleanup, resume quotidien)
- Couverture hooks : 5/13 -> 9/13 evenements geres
- Frontmatter YAML pour ~100 agents (5 langues) : model (haiku/sonnet selon le role), tools (whitelist explicite), disallowedTools (restrictions securite), skills (contexte precharge)
- Frontmatter skills : allowed-tools, model, triggers ameliores (patterns fichier + mots-cles)
- Plugin manifest (`.claude-plugin/plugin.json`) pour distribution marketplace
- Settings etendus : plansDirectory, permissions elargies, deny rules renforcees

Les reviewers tournent sur haiku (rapide, economique). Les architects sur sonnet (raisonnement approfondi). Chaque agent declare exactement les outils dont il a besoin.

Exploiter 40% d'un outil, c'est payer 100% pour utiliser la moitie. La v5.2 corrige ca.

Fin de la serie. claude-craft est passe de 90 a 130+ commandes, de 25 a 35 agents, en 11 releases. Open source, disponible maintenant : https://github.com/TheBeardedBearSAS/claude-craft
